# Задача: метки «רב / תלמיד» и абзацы — в live и в сверке транскрипта

Поставлено: 2026-11-04. Сервер — ai-trns (этот репозиторий), клиент — `../ai-tools` (страницы `/live` и `/compare`).

## Зачем
Сейчас и live (`תמלול חי`), и сверка (`השוואת תמלול`) выдают сплошной текст чанками. Человеку, который читает или
сверяет урок, нужен текст **как в отредактированной расшифровке**: реплики разделены по говорящим, текст Рава
разбит на абзацы.

## Метки говорящих (решено с пользователем)
| Метка | Кто | Как отличить |
|---|---|---|
| `רב` | Рав | образец голоса (`speakers/Rav`) |
| `קריין` | **чтец** — читает источник вслух | отдельно от учеников. Варианты: (а) образцы голоса постоянных чтецов; (б) **по тексту**: сегмент не-Рава, который дословно совпадает с текстом источника урока (связь урок → источник есть в MDB, выравнивание — `tadiff`). (б) не требует образцов и сразу даёт «где читали п. N» — проверить его первым |
| `תלמיד` | все остальные (вопросы, ведущий, переводчик) | всё, что не Рав и не чтец |
Имена людей не писать. Метки задать в `labels.py` (`NAMES`), не хардкодить в клиенте.
Шире: это первый слой разметки урока (кто говорит → где чтение источника, где объяснение, где вопрос). На нём стоит
прототип «пункт источника → момент урока» (`~/projects/work-strategy/pitches/fragment-prototype.md`).

## Шаг 1. Сверка (offline) — сначала, она проще и даёт замер
1. Цепочка для урока: транскрипция → diarize (слова со спикером) → абзацы внутри реплик Рава → документ
   `[{speaker, start, end, text, words}]` (абзац = непрерывный кусок одного спикера; у Рава — разбит моделью).
   Отдать как формат результата (`?format=paragraphs`) или отдельный вид задачи — как удобнее клиенту.
2. Абзацы режутся **внутри** реплики одного спикера; смена спикера — всегда новый абзац.
3. Клиент `/compare`: колонка «תמלול אוטומטי» — по абзацам с меткой «רב:» / «תלמיד:» и таймкодом абзаца; клик по
   метке/таймкоду — перемотка. Подсветка различий и пометки ошибок не ломаются.
4. **Бесплатный замер качества:** в отредактированных расшифровках реплики уже помечены (`הרב:`, `ש:`). При сверке
   сравнить метки человека с метками модели → доля слов с верным спикером, число пропущенных/лишних смен спикера.
   Сравнить абзацы модели с абзацами человека (exact / ±1 предложение, как в `eval.py` mdb-lora).

## Шаг 2. Live
1. **Спикер в live.** Полная диаризация на потоке не нужна: нужны три метки `רב` / `קריין` / `תלמיד`. Предложение:
   эмбеддинг голоса для каждого подтверждённого (LocalAgreement) сегмента → сходство с образцом Рава → `רב`;
   иначе, если текст сегмента совпадает с текстом источника урока (или голос — с образцом чтеца) → `קריין`; иначе `תלמיד`.
   Если не уверен — метка того же спикера, что у предыдущего сегмента, с флагом `tentative`.
   Альтернативы (pyannote на скользящем окне) — только если простой вариант даёт плохое качество; сравнить на записи.
2. **Абзацы в live:** новая строка при смене спикера и при паузе > N с (подобрать по записям). Модель абзацев
   в live — только если укладывается в задержку; иначе опционально переразбить абзац Рава, когда он закрылся.
3. **События SSE:** у сегмента поле `speaker` (+ `tentative`), событие `paragraph` (начало нового абзаца). Позднее
   уточнение метки — отдельное событие `relabel` с id сегмента, клиент перерисовывает.
4. **Google Doc:** новый абзац при смене спикера, префикс «רב:» / «תלמיד:» (жирным), RTL как сейчас.
5. **Клиент `/live`:** показывать метки и абзацы; переключатель «הצג דוברים», если метка мешает.
